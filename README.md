# xkb-for-macos

PC keyboard layouts for MacOS straight from X11 xkb.

Thanks to [klfc](https://github.com/39aldo39/klfc),
we converted all keyboard layouts from an Ubuntu release distribution (currently 24.04, xkb-data)
to MacOS (keylayout).

Outcome: type on your Mac the same way you would type on a PC.


## Installation

You can either do the following in `/Library/Keyboard Layouts` for all users (recommended)
or `~/Library/Keyboard Layouts` only for your own user.

The preferred way is to clone this git repository

> **WARNING** This wipes everything already in `/Library/Keyboard Layouts`,
> including any layout files you added yourself and did not check in here.
> Back them up first if you want to keep them.

```
sudo rm -rf /Library/Keyboard\ Layouts
sudo git clone https://github.com/ysoftwareab/xkb-for-macos.git /Library/Keyboard\ Layouts
```

If you want to avoid the nuke-and-reinstall, copy the layouts you want instead:

```
sudo cp y-xkb-se.keylayout /Library/Keyboard\ Layouts/
```

Note that the numeric `id` of each layout is only stable within one
`xkb-data` release (`XKB_VSN` in the Makefile). macOS picks duplicates by
filename so upgrades replace cleanly — but a few variants drop or rename
across releases; after an update, prefer to reinstall rather than assume
ids or file names are still there.

You can then activate the `ysoftwareab xkb <language>`
via `System Settings` - `Keyboard` - `Keyboard (tab)` - `Input Sources`. (macOS 13 and later; older macOS still calls this `System Preferences`.)

**NOTE** If you are having issues activating a keyboard,
try the following and restart ([source](https://apple.stackexchange.com/q/21691/31369)).

```
sudo rm /System/Library/Caches/com.apple.IntlDataCache*
sudo find /var/ -name "*IntlDataCache*" -exec rm {} \;
```


## But why?

The reasons stem from the Swedish keyboard layout on MacOS.

Basic keys for programming are a killer to reach:

* `|` is `Right Option + 7`
* `\` is `Shift + Right Option + 7`
* `{` is `Shift + Right Option + 8`
* `}` is `Shift + Right Option + 9`

Same keys on PC:

* `|` is `Right Option + <`
* `\` is `Right Option + +`
* `{` is `Right Option + 7`
* `}` is `Right Option + 0`

Similar issues surface in other languages as you can see in Related Work.

What is different from other initiatives is that this is not a manual conversion.

For a visual diff, please consult the original MacOS keyboard layout [se.pdf](se.pdf)
and the PC keyboard layout [y-xkb-se.pdf](y-xkb-se.pdf), as exported by [Ukelele](https://software.sil.org/ukelele/).


## Hand-maintained overlays (ro, se)

The plain `se` and `ro` layouts (not the `-variant` ones) carry extra
macOS emacs bindings on top of the generated output: `<keyMap index="8">`,
triggered by `anyControl`, so `C-a`, `C-e`, `C-n`, `C-p`, `C-k`, `C-y`,
`C-d`, `C-b`, `C-f`, `C-l`, `C-u`, `C-t` and friends work inside text
fields wherever macOS lets a layout shape keys.

They are *not* generated by `make`/klfc: they get applied as overlay
patches right after generation.

**Do not edit `y-xkb-{ro,se}.keylayout` by hand** — the next `make`
regenerates from xkb-data and any hand edits are lost. Instead:

1. Regenerate to see the base layout intact.
2. Change the bindings by editing `macos-emacs-bindings-ro.patch` /
   `macos-emacs-bindings-se.patch` (add lines inside `<keyMap index="8">`).
3. Re-run `make` and the patches reaply on top.

If a patch stops applying cleanly (upstream xkb reshuffled ro/se enough
between releases), regenerate, re-apply your emacs additions on the new
layout, and save the result as a fresh `.patch` replacing the old one.

## Upgrading

Upstream xkeyboard-config drops and renames variants between releases
(2.29-2 → 2.42-1ubuntu1 dropped ~50 variants and added ~117 new ones).
If a layout you had installed disappears from this repo after an upgrade,
your existing input source for it goes stale and must be replaced:

1. Pick a replacement across the remaining variants for that country.
2. Remove the old input source from `System Settings`, add the new one.
3. Also see the cache-reset NOTE above if the picker still misbehaves.

The `<keyboard id=N>` in each `.keylayout` is regenerated per release and
is only meaningful relative to the same xkb-data version. Duplicates or
missing flags after an upgrade are usually the cache (see NOTE above), not
the id.
